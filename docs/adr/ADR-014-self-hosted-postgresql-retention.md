# ADR-014: PostgreSQL을 앱 EC2에 직접 설치하고, 필요한 데이터만 2일 보관한다

- 상태: 채택 (2026-09-30). **DB 위치(결정 1과 2의 EC2 설치 부분)는 ADR-015(Neon Free, 2026-10-01)로 대체.** 결정 3·4(필요한 것만, 2일 보관, S3 원문 폐기)는 유효하다.
- 갱신(2026-10-01): 운영 DB는 Neon Free(ADR-015), RDS 미사용(ADR-016), AWS 미사용(ADR-017). 이 ADR의 EC2·RDS·S3 언급은 기록이다. 보관 기간(2일/8일)은 ADR-018(수집 데이터 12시간, 이력 2일)로 대체됐다.
- 관련: ADR-013(PostgreSQL 18), `docs/DB-PLAN.md`(세부 계획)

## 배경

- AWS Free 플랜 계정은 6개월이 지나거나 크레딧을 다 쓰면 자동으로 닫히고, 90일 뒤 삭제된다. 그래서 장기 운영에는 Paid 플랜이 필요하다 [확실, AWS Billing 문서].
- 무료 기간이 끝나면 비용은 다음과 같다 [추정].
  - RDS db.t4g.micro: 월 약 $21
  - EC2(t4g.small), EBS, IPv4: 월 약 $21
- 무료 관리형 DB도 검토했다.
  - Neon Free: 0.5GB, 싱가포르 리전
  - Supabase Free: 500MB, 서울 리전
- 로컬 실측에서 예보 테이블은 14일 보관·12개 항목일 때 350MB였다. 3일 보관·6개 항목으로 줄이면 DB 전체가 39MB였다.
- 사용자는 방안 ①(같은 EC2에 직접 설치)을 골랐고, 보관은 2일로 하고 서비스에 필요한 것만 저장하라고 지시했다.

## 결정

1. PostgreSQL 18을 앱과 같은 EC2(t4g.small, AL2023 arm64)에 설치한다.
   - AL2023 core 저장소의 `postgresql18`을 쓴다 [확실, 2023.10.20260330 릴리스 노트].
   - `localhost`에서만 접속을 받고, 비밀번호는 SSM SecureString에 둔다.
   - 매일 `pg_dump`로 S3 `backup/db/`에 백업하고 7일 뒤 지운다.
2. RDS 호환을 유지한다.
   - `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`만 바꾸면 RDS for PostgreSQL 18에서 그대로 동작해야 한다.
   - 확장, 슈퍼유저 전용 SQL, 로컬 전용 문법은 쓰지 않는다. 슈퍼유저가 아닌 소유자 계정으로 마이그레이션되는지 테스트로 확인한다.
   - 과제 시연에 RDS가 필요하면 시연 기간에만 RDS를 쓴다. 그 뒤에는 최종 스냅샷을 만들고 삭제한다(DB-PLAN 5.7, ADR-015 이후에는 11.9).
3. 필요한 것만, 2일 보관한다.
   - 예보는 (격자, 예보 시각)마다 1행에 서비스가 읽는 6개 항목(SKY, PTY, TMP, REH, WSD, POP)만 둔다. 테이블은 `kma_forecast_hour`다.
   - 읽는 곳이 없는 테이블 4개와 컬럼 약 24개를 지운다.
   - 2일보다 길게 두는 것은 근거가 있는 네 가지뿐이다.
     - 운영 이력 8일: G6 "7일 연속" 판정과 관리자 이력 화면
     - 천문 달력: 지난달 1일부터
     - 적중률 스냅숏 32일: R1에서 도입
     - 팩: manifest가 가리키는 현재 팩, 종류별 최신 3개, 고정(pinned) 팩
4. S3 원문 보관(`raw/`, 120일)과 `collect-only` 프로필은 폐기한다. 적중률에 필요한 예보 값은 수집할 때 `forecast_verification`에 바로 기록한다(C9, 기한 2026-11-28).

## 결과

- 앱이 받는 팩(스키마 2)은 바뀌지 않는다. 골든 해시 테스트로 확인한다.
- DB 전체는 수 MB에서 15MB 이하로 예상한다 [추정]. EC2 첫 주에 실측해 DB-PLAN 6.3에 기록한다.
- 이틀보다 이전 밤은 다시 발행할 수 없다. ETL이 2일 넘게 멈추면 현재 팩이 그대로 유지되고, 신선도 알람이 이를 잡는다.
- (ADR-015로 대체: DB는 Neon) 앱, DB, 캐시가 EC2 한 대에 있어 단일 장애점이다. 손실 범위는 마지막 덤프 이후 최대 24시간이고, 팩은 S3에 남는다.
- (ADR-015로 대체: t4g.micro 재검토, DB-PLAN 11.6) 메모리가 모자라 t4g.micro로 줄이는 경로는 폐지한다. 2027년부터 월 약 $21이다 [추정].
- 구현과 검증(2026-10-01): DB-PLAN 10장. AL2023 컨테이너 배포 검증 47/47, EC2 메모리 모사 647/1,600MiB, 테스트 57/57.
