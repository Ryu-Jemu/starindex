# ADR-018: 데이터 수명 주기 — 수집 데이터 12시간, 이력 2일, 밤 경계 06시

- 상태: 채택 (2026-10-01, 사용자 결정)
- 대체: ADR-014의 보관 기간(예보·밤 데이터 2일, 이력 8일, 달력 "지난달 1일부터"), DB-PLAN 2.2의 기간 표, SERVICE-PLAN 4.2의 "밤 날짜 = 12시 기준"
- 유지: 저장 대상(서비스가 읽는 6개 항목만, `kma_forecast_hour`), 팩 보존 규칙(현재·종류별 최신 3·고정), 정리 항목을 따로 실행하고 실패하면 경고만 남기는 방식

## 배경

- 사용자 지시(10-01): "데이터 수명 주기를 설정하자. 주기적으로 Producer로 폴링 후에, 해당 시간이 약 12시간이 지나면 db에서 삭제하면 용량을 지키면서 수행이 가능해보인다."
- 범위 확인 답: "데이터 12시간, 이력 2일". 이어서 '오늘 밤'의 경계는 06시로 정했다(A안).
- Producer는 3시간마다 도는 수집 Job(`forecastPipelineJob`, GitHub Actions 예약 실행)이다.
- 실측(10-01): 예보 1회 수집은 1,020행·256kB, DB 전체 8~9MB, Neon Free 한도 512MB. 12시간 규칙은 용량을 지키는 장치이고, 데이터를 필요 이상 오래 두지 않는 설계 원칙이기도 하다.

## 결정

| 데이터 | 수명 | 기준 |
|---|---|---|
| `kma_forecast_hour`(수집한 예보) | **12시간** | **예보 시각**(`fcst_at`)이 12시간 지난 행. 수집 시각으로 세면 수집이 12시간 넘게 끊겼을 때 앞으로 3일치 예보까지 지워지므로 쓰지 않는다 |
| `kasi_riseset`, `star_index_nightly` | 그 밤이 지나면 | 밤 날짜 < 현재 밤(06시에 바뀜). 밤이 끝나고 약 12시간 안에 지워진다 |
| 천문 달력(`kasi_astro_event`, `kasi_special_day`, `kasi_lunar_day`) | 그날이 지나면 | 날짜 < 현재 밤. R3에서 한 달 보기 화면이 필요하면 다시 정한다 |
| 이력: `etl_api_call`, `astro_crosscheck`, `data_pack`과 팩 파일, Spring Batch 메타데이터 | **2일** | 현재 팩·종류별 최신 3개·고정 팩은 항상 남긴다 |

- 정리 시점: **매 수집 실행의 끝**(`forecastPipelineJob`의 마지막 단계, 3시간마다)과 매일 00:40(`astroDailyJob`). 그래서 어떤 데이터도 수명을 한 번의 실행 간격(3시간) 이상 넘기지 않는다.
- 하한(설정 실수 방지): 수집 데이터는 12시간 이상이다. 그 밤의 마지막 실행(05:20)이 어제 저녁의 첫 어두운 시각(19시 무렵) 예보까지 읽어야 하기 때문이다. 이력은 1일 이상이다(하루치 실행 8회, 24시간 무인 운영 판정, 관리자 화면).
- 설정: `starindex.etl.data-retention: 12h`, `history-retention: 2d`(기간 표기).
- **밤 경계 06시**: `IndexService.nightDateOf`와 앱 `NightDate.of`를 같이 바꿨다. 06시부터는 다가오는 밤이 '오늘 밤'이다.
  - 08·11시 발표로 그 밤 지수를 일찍 발행한다.
  - 정오 경계였다면 08·11시 실행이 지난밤을 다시 계산하려고 12시간이 지난 어제 18시 예보를 찾았을 것이다.

## 결과

- 용량: 예보는 정상 상태에서 약 17개 지점 × 72시간분이다(수백 kB, 추정). 이력은 이틀치다.
- 잃는 것
  - 어젯밤 지수를 다시 만드는 일(`publish nightDate=<어제>`)은 06시 이후 데이터가 없어 안 된다. 그 밤의 마지막 팩은 버킷에 남는다.
  - 관리자 실행 이력은 2일까지다. 7일 연속 성공(G6) 판정은 GitHub Actions 실행 기록으로 한다.
  - 달력은 지난 날짜가 없다.
- 검증: 백엔드 86/86(표별 경계 ±1초·±1일, 06시 경계, 수집 중단 때 앞으로의 예보 보존, 하한), SkyCore 75/75(06시 경계), 로컬 끝단(`scripts/etl-local-e2e.sh`)에서 파이프라인 끝 정리 단계 동작.
